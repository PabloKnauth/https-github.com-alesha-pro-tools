# Diseñar manuales corporativos claros y fieles

## Objetivo
Transformar documentación en un soporte visual profesional, coherente con la marca y fácil de consultar **sin sacrificar precisión**. Esta habilidad se ocupa de presentación, navegación y recursos gráficos; no sustituye aprobación del contenido ni crea políticas.

## Modo protegido: «solo diseño»
Si el usuario solicita **conservar toda la información**, «contenido intocable», «idéntica estructura y texto», «cambiar únicamente imagen» o similar:
1. Considera el texto, cifras, nombres, orden solicitado, tablas, notas, advertencias, instrucciones, anexos y significado como **material protegido**.
2. No resumir, corregir ortografía, reescribir, suprimir, fusionar, añadir pasos, renumerar o reorganizar contenido sin autorización. Si el usuario permite reflujo de páginas, conservar secuencia lógica y exactitud.
3. Se permiten cambios de portada, márgenes, tipografía, jerarquía visual, colores, espaciados, iconografía de apoyo y disposición; **no cambios de contenido**.
4. Si algo parece incorrecto, colocar observación **fuera del documento** y pedir autorización para una versión de contenido distinta.
5. Comparar fuente vs resultado de forma sistemática; no afirmar preservación total si las fuentes no son legibles o la comparación no pudo completarse.
6. Los logos deben ser **originales proporcionados o recuperados de fuente autorizada**; no recrear un logotipo oficial inventado ni alterar su geometría. No superponer el logo sobre texto ni elementos.

## Método de diseño
### 1. Brief visual
Identificar empresa, identidad oficial, destino (digital / impresión / uso en campo), tamaño carta/A4 u otro solicitado, público, nivel de lectura, soporte de consulta y contenido protegido. Si no hay manual de marca, proponer diseño explícitamente provisional; **nunca atribuir a una empresa colores o tipografías no confirmados**.

### 2. Sistema visual
Definir paleta con funciones, contraste, tipografías legibles, escala de titulares, retícula, márgenes, cabeceras, pies, número de página, tablas y espacios de respiración. Si un color corporativo no cumple contraste para texto pequeño, usarlo en acentos, no en texto ilegible.

### 3. Arquitectura visual
Dar prioridad a orientación y búsqueda: sumario funcional, separadores por proceso, títulos orientados a tareas, pasos numerados, avisos con palabras explícitas («Advertencia», «Verificar»), recuadros solo cuando tengan función. Una advertencia no debe depender solo del color.

### 4. Recursos gráficos
Elegir diagramas de decisión para rutas, fotografías auténticas para objetos/acciones reales, tablas para comparar opciones y checklists para ejecución. No introducir diagramas que cambien decisiones o creen nuevos protocolos.

### 5. Producción y control
Verificar saltos de página, desbordamientos, imágenes pixeladas, alineaciones, solapamientos, numeración, elementos cortados, fuentes y contraste. Previsualizar páginas completas. Cuando exista PDF o DOCX editable, trabajar con fuente editable si es posible; no prometer equivalencia perfecta tras OCR o extracción defectuosa.

### 6. Entrega
Si el usuario solicitó archivo, entregar ese formato cuando sea posible; idealmente versión final y fuente editable si se pide. Si no se puede producir un archivo, entregar maqueta o especificaciones claramente identificadas, sin afirmar que existe un PDF.
